# frontend-guidelines —— 前端改动检查清单

> 用途：给「界面改动」当开工与验收标准。改动前读「改前检查」，写代码时对照四类规则，改完跑「改后验证」。
> 原则：规则里每一条都来自本项目真实踩过的坑，不是风格偏好——违反会出真 bug。

## 一、页面层级（叠放与显隐）

1. **`[hidden]` 必须永远生效**：类选择器（如 `.mask` 的 `display:flex`）会盖掉浏览器给 `hidden` 属性的默认 `display:none`。全局写 `[hidden] { display: none !important; }`，新弹层一律用 `hidden` 属性控制显隐，不用 class 拼接。
2. **浮层 z-index 只允许固定几档**，新浮层不许随手写值：
   - 普通固定元素 / 吸顶：≤ 10
   - 底部选择面板（picker）：40
   - 轻提示（toast）：60——必须高于一切浮层，否则「面板里点了没反应」其实是提示被盖住了
   - 新增层级先查现有档位，能复用就不加新值；确需新档，注释写清「必须高于谁、为什么」。
3. **弹层关闭后必须真正移除拦截**：`hidden` 摘掉之前，遮罩不许残留半透明背景或继续吃点击。
4. **通知出口分级**：字段级错误写在字段旁（hint/error 文案），操作结果用轻提示，整页级通知才用顶部横幅。不许用原生 `alert/confirm`。

## 二、颜色和字体

1. **颜色只走 CSS 变量**（`--c-*`），不写裸色值；语义色分工固定：主色（操作）、危险红（删除/错误）、警示黄底（提示横幅）。换肤=只覆盖品牌色变量，警示色/字号/圆角不许被皮肤改动。
2. **字号一律 `var(--t-*)` 令牌，禁止裸 px**；正文字号只有一档基准，层级优先靠**字重**（400/500/600/700）和留白表达，字号能不加就不加。
3. **`line-height` 必须无单位**（随字号缩放）；固定高度用 `height` + flex 居中，不用行高凑。`letter-spacing` 用 `em` 不用 px，字号越小越要正字距。
4. **对比度硬线**：正文对底色 ≥ 4.5:1；「弱但必须能看清」的文字用专用弱化色（对白底 ≥ 4.5:1），不许再淡。深色文字配浅底、浅色文字配深底，随主题走。
5. **占位/空态也是内容**：空列表要有可读文案（如「今天没有课」），不许留白块。

## 三、卡片与按钮

1. **圆角、间距走全局变量**（`--radius`、`--gap`），同类组件数值必须一致；卡片=白底 + 1px 边框 + 统一圆角，不堆阴影。
2. **按钮分级明确**：主操作（实心主色）一屏一个；次操作（描边/ghost）；危险操作用危险色并**必须二次确认**（确认弹窗，不用原生 confirm）。
3. **每个可点元素三态齐全**：`:hover`（仅指针设备）、`:active` 按下反馈（`scale(0.97)` + 100–160ms ease-out）、禁用态（降透明度，不用 `disabled` 属性锁焦点）。
4. **点击目标必须是整块可点**：卡片内按钮不重叠；点击判定区域 ≥ 视觉区域；事件委托时按 class 整词匹配目标，禁子串误伤。

## 四、移动端适配

1. **触屏可点元素最小 44×44px**（含内边距），排不下就缩视觉、不缩热区。
2. **触摸设备输入框字号 ≥ 16px**（`@media (pointer: coarse)`）：iOS 聚焦 <16px 输入框会自动放大页面且不缩回。
3. **所有 `:hover` 必须包在 `@media (hover: hover) and (pointer: fine)` 里**——触摸屏会被伪造 hover，点完颜色卡住。
4. **底部固定区域必须加 `env(safe-area-inset-bottom)`**，且页面 `viewport` 带 `viewport-fit=cover`。
5. **触屏基线三件套**：`-webkit-tap-highlight-color: transparent`、`touch-action: manipulation`、外层 `overscroll-behavior: none`。
6. **媒体查询顺序**：能力类（`pointer`/`hover`）放文件末尾；版面类（`max-width`）必须排在被覆盖规则之后——同优先级靠书写顺序定胜负。
7. **窄屏优先设计，宽屏做增强**；横向放不下的表格用「收紧 + 横向滚动 + 自动定位到相关列」，不许溢出页面宽度。

## 五、修改前检查

1. **相对路径**：资源引用一律 `./` 开头，禁止绝对路径——子路径部署下绝对路径直接 404 白屏。
2. **改了 css/js 必须 bump 引用版本号**（`?v=YYYYMMDDx`，一天多次改动递增后缀），否则用户浏览器拿旧文件配新文件，出「改了没生效」的怪错。
3. **动数据结构前先查兼容**：新增可选字段通常不用升 `schema_version`；改字段含义/类型/必填性必须升版本 + 写升级函数，判断理由写进技术设计文档。
4. **动数据模型或功能范围，三份文档同步**（设计方案 / PRD / 技术设计），只改代码不算完成。
5. **分层纪律**：数据只进/出数据层唯一闸门；纯计算不碰 DOM 和存储；渲染层只画不存。新逻辑先问「该住在哪一层」，不许跨层直连。

## 六、修改后验证

1. **静态检查**：JS 语法/括号配平、CSS 括号与选择器完整性——用检查脚本跑，不靠肉眼。
2. **功能点击测试必须过**：静态全绿 ≠ 没 bug，涉及点击/输入的改动要有 DOM 级交互测试（事件绑定、状态流转、边界值）。
3. **旧数据回归**：动了存储结构的，用改动前的数据实测「读得出、不丢字段」。
4. **真机/多宽度实测**：至少三档——手机宽（390px 级）、桌面宽、`file://` 直开；F12 Console 无红色报错。
5. **检查器自证**：新写的检查脚本先注入一条已知坏样例，确认它**真的会报红**（注入后文件必须确认真的变了），否则检查器可能静默假通过。
6. **验证结论给证据**：命令输出、页面截图、测试结果，不接受「应该没问题」。
