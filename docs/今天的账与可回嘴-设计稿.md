## 零、先读这两条纠错

讨论中我（AI）对录音功能有过两次误解，以下为定稿事实，**实现时不要继承错误前提**。

| 纠错 | 事实 |
|---|---|
| **录音不进任何统计** | 录音**只用于提取课堂内容、辅助自动安排日程**，是**选择性开启**的，不是 24 小时监控，不参与复盘分析。所以「静默时长 = 走神」这类推论全部作废（走神雷达已撤回）。 |
| **数据源只有两路** | ① **日程完成度**（待办 + 当日其他日程；**课表只是背景，不参与对照**）② **手机应用使用时间**。 |

**由此废弃的两条设计：**

- 「三层时间轴（睡眠 / 课表 / 手机）」——课表每天是常数，进对照会冲淡关系；且三路时间**不可相减**（上课时本来就在用手机，相减会算出负数）。
- 「走神雷达」——见上，录音不参与分析。

## 一、功能一：「今天的账」

### 1.1 它是什么

每天一次的个人结算播报。对照两路数据 —— **你自己说的话，你做到几成** vs **手机实际怎么用的**。

产品主张只有一句：**你的计划和你实际过的日子差多远。** 课表 App 知道你的课表，屏幕时间 App 知道你的屏幕，但没有一家知道两者对不上的地方。

### 1.2 结构（两栏，不是时间轴）

| 栏 | 内容 | 交互 |
|---|---|---|
| **主栏** | 日程完成度：排了 N 件事，做完 M 件 | 常显，播报的事实基础 |
| **副栏** | 手机使用：分类汇总 + 分时段分布 | **默认折叠**，一行 `手机 6h32m ▸` |

**关键交互约束：只看主栏就能拿到 90% 的价值。** 用户会先看日程栏，手机栏是可下钻的对照面板。播报事实以主栏为主，手机栏作对照。

### 1.3 职责分离（不可违反）

> **规则负责「算哪个数」，AI 只负责「说哪句」。**

- **规则版**：本地纯 JS，算出全部事实。**永远存在、零延迟、离线可用，永远是降级路径。**
- **AI 版**：只做两件规则做不好的事 ——
  1. **挑今天最值得说的那一笔**（否则模板念叨 30 天就没人看了）
  2. **把同一份数字讲出 30 种说法**（措辞多变是复盘能被看下去的前提）
- **AI 不许生成事实。** 所有事实来自规则模块输出。**语气规则库 + 事实约束 = 可爱 × 不幻觉。**

一句话概括 AI 的职责范围：**AI 决定「说哪句」，规则决定「算哪个数」。**

### 1.4 调用方式（已定）

- **前端直连 DeepSeek**，即时生成，**不挂云函数、不做预生成**（DeepSeek 秒出，预生成的调度 / 幂等 / 提醒档同步全是白付的复杂度）。
- 流程：进复盘页 → 规则账**立刻**显示 → AI 请求发出 → 秒级填充。**「等待」状态不存在。**
- AI 挂了 / 离线 → 只有规则版，功能不残。
- 规则版与 AI 版**解耦**：AI 层是升级，不是前置依赖。

⚠️ 技术提醒：`VITE_` 前缀变量在 build 时静态内联进 bundle，也会打进 APK，可被提取。这是已知取舍，不是阻塞项；但**别把它硬写进源码再 commit**（`AGENTS.md` 五.3 密钥不进提交）。

### 1.5 语气（已定）

- **二次元可爱风**
- **人格 = 通知栏里那个东西。** 不另造角色 —— `StatusFrameStore.kt` 的状态框本来就住在通知栏、已经有「谁在说话」的模糊身份，播报由同一角色说，产品人格才是连续的。
- **立场：站在你这边，但不给你台阶。**
- **可爱在措辞，不在数字**：数字永远精确冷硬，AI 只负责措辞。

参考文案（方向已认可）：

> **今天也结账啦～**
>
> 你排了 6 件事，做完了 3 件。
> 手机今天陪了你 6 小时 32 分。
>
> 两条记录都放这儿了。哪条更真，你说了算。
> 手机分布 ▸
>
> 今天主笔：**待办连续 3 天停在三成。**
>
> ▸ 补记今天没做的 3 件事

硬约束：

- **全文只调侃一句。** 可爱放多了就失效，因为它就不再敢戳你了。留一句比留十句有用。
- **动作 1–2 个。** 给三个就变成菜单，菜单 = 没人点。

### 1.6 动作映射（上限 2）

| 账里发现 | 给的动作 |
|---|---|
| 有日程没标完成 | 补记今天没做的 N 件事 |
| 待办有多条没动 | 去处理待办 |
| 明天 N 节课 | 看明天的课表 |
| 未授权使用情况访问 | 去开启（**只催一次**） |

通知点击直达对应面板的链路**真机已验过**（`localNotificationActionPerformed` → `[data-review-q]` 等，见 `docs/真机复验清单.md` #16/#20/#21），可直接复用。

### 1.7 基线（已定）

- **窗口 8 天**，取最近 8 天建基线。
- **硬规则：攒够之前不许硬凑对比。** 不说「比昨天少 30 分」这种无处可依的话。
- 显示 `基线建立中（3/8 天）`。
- 无授权时明说「手机数据不全」，**不要假装完整**。

### 1.8 手机栏呈现的三条规矩

1. **画成分布条，不列清单打分。** 「微信 3h12m 排名第 3」= 道德审判。分布条让用户自己看、自己得出结论。
2. **沟通类单列，不归娱乐。** 微信在大学是学术基础设施，跟抖音放一起算是一句谎话。
3. **隐私：只送分类汇总给云端，不送 App 名。**「社交 3.5h / 学习 1.5h」足够 AI 写好句子；「微信 3.5h、抖音 1.2h」不必离开手机。

### 1.9 手机使用数据的权限坑（已知）

- 需要 `PACKAGE_USAGE_STATS`，用户**必须手动**去设置开「使用情况访问权限」。
- 与 `docs/交接说明.md` §6.6 的精确提醒同类问题：侧载包 `installerPackageName=null` → Android 13+「受限设置」可能锁灰，需先手动放行一次。
- 处理原则：**可选、降级、不催。** 没授权就显示「未开启」并告知路径，不反复拦。（已有一个特殊权限要手动放行，再加一个体感会变差）

### 1.10 明确否决的（别做）

| 否决项 | 原因 |
|---|---|
| **今日效率分 / 任何总分** | 数据凑不出真相，看上去最像「量化自我」但只是粉饰，且产生打分压力 |
| **真实专注时长** | 上课用手机是正常行为（记笔记 / 看题），不存在干净对上的那段 |
| **睡眠时长** | 无健康数据权限、无手环 |
| **三路时间相减** | 会算出负数（上课时本来就在用手机） |
| **留白式提问**（「你记得那节课讲了什么吗」） | 已由「可回嘴」以更便宜的方式替代 |
| **App 使用时间列清单打分** | 变道德审判，见 §1.8-1 |

### 1.11 唯一真正的新算法：时段错位

两路数据放在一起，只有一种算法能产出新东西：**「该认真时段」 vs 「手机使用高峰」的时间位置。**

取日程高峰区间与 App 使用高峰区间，重叠部分 = 手机占用打断日程时段。

> 「晚上 8 点到 10 点，你手机里社交类 App 用了 2 小时 14 分。同一时间窗里，你给自己排了 2 项日程 —— 其中 1 项没做。」

这是全 App 里唯一一处**手机数据真正参与计算**，而不是被念出来。

注意：**重叠并不等于「浪费」。** 上课刷手机、讲座刷手机都正常。措辞不要下判断。

## 二、功能二：可回嘴 + 找模式（**当成一件做**）

### 2.1 为什么是一件

同一个引擎：**它记住了，并且指出来。** 区别只在于这次是谁先看见 —— 是你，还是数据。

| | 谁发现的 | 引擎 |
|---|---|---|
| 可回嘴 | 你给一个理由 → 它记住 → 下次指出来 | 规则 + 存几句你的借口 |
| 找模式 | 数据显出重复 → 它命名 | 同一台记忆存储 + 同一个「指出来」的界面 |

做了可回嘴，「它会指着你过去说过的话」就成立了；「你这月断了三个周三」只是多一条数据源。**边际成本接近零。**

### 2.2 可回嘴：还嘴但会免（已定）

**核心原则：一个从不放过你的问责搭子，用两周就会被关掉通知。**

| 机制 | 规则 |
|---|---|
| **还嘴** | 把你的原话原样甩回来（「又是下雨天？」） |
| **会免** | 提过一次后自动闭嘴一段时间 |
| **降级** | **同一件事第三次提起时，它自己先软下来**：「好吧，这事儿我不提了。」—— 这句比任何还嘴都让人喜欢，因为它证明它听得懂「我知道了」 |
| **过期** | **超过 30 天的理由自动不引用。** 三个月前的借口甩出来不是厉害，是刻薄 |

不用 LLM 对话，就是规则 + 存几句你的借口。成本极低，有趣度极高。

**可主动提起（已定：能，一个月最多一次）**，硬约束：

- 必须**只在模式成立时**（「你这三个周三」），不是随手甩。
- 一个月最多一次。

**实现要点：** 引用存储 = 「理由 + 提出次数 + 最后一次时间」三元组。

### 2.3 找模式：它唯一的敌人是「废话」

最典型的翻车是生成正确的废话：

> 「你在工作日的完成率高于周末。」← 真，但零信息量

**沉默规则：**

- **证据 < 3 次 → 只给事实陈述，不给结论。**
- **证据 ≥ 3 次 → 才允许命名。**

**陈述 vs 命名必须分开：**

| | 例句 | 性质 |
|---|---|---|
| **陈述**（事实） | 「这三个周三都是下午有课的日子。」 | 用户自己验证 |
| **命名**（它的判断） | 「你周三下午认输了。」 | 它的观点 |

**默认只做陈述；命名留给 AI，且必须够格才做。**

**纪律延伸：规则允许沉默，AI 不允许。**（与 §1.3 同一套）

### 2.4 延伸：取消「连续天数」

连续天数无趣，且**奖励那些本来就不容易断的人**，断一天归零最挫败。

改成**找模式**：「你这个月断了三个周三，全是下午有课的日子。」不累计、不比较、不评判，只把断点连起来让你看见。数据已有，只是换问法。

## 三、功能三：通知栏清算台（**已暂缓**）

### 3.1 已查证的硬约束

Android 普通通知**最多 3 个 action 按钮**，已在本机 SDK 源码中验证：

```java
// C:\Users\26502\AppData\Local\Android\Sdk\sources\android-37.0\android\app\Notification.java:322
public static final int MAX_ACTION_BUTTONS = 3;
```

框架自己的计数循环会真的截断：

```java
// Notification.java:7435-7456
int actionsCounted = 0;
for (int i = 0; i < mActions.size(); i++) {
    actionsCounted++;
    candidates.add(new ActionButton(action, i));
    if (actionsCounted >= MAX_ACTION_BUTTONS) break;   // 到 3 就停
}
```

源码注释写明：**故意不让第 4 个按钮「翻页」进来**（"whenever we skip an action do not allow those past the 3d one to 'page in'"）—— 所以「折叠起来能看到更多」这条退路也不存在。

现状正好占满：`D:\Document\Project\vibe-coding-project-app\scripts\native\StatusFrameService.kt:113-136` 的 `canRec` / `canClassDone` / `canListen` 三枚，上课时全亮。

> **口径诚实**：读的是 `android-37.0`（预览平台）源码，项目 `android/variables.gradle:2-4` 是 `compileSdk 35 / targetSdk 35`。该常量自 API 16 起未变，结论在 35 上不变，但严格说数字来自 37.0 源码。

**逃生舱存在：** `Notification.Builder#setCustomContentView(RemoteViews)`（`Notification.java:5773`）—— 自绘布局里的按钮不是 `Notification.Action`，不受该限制。

### 3.2 三条路的成本

| 路径 | 做什么 | 成本 | 拿到什么 |
|---|---|---|---|
| **A（推荐）** | 在现有 `broadcastAction` 管道上加一枚「结账」按钮，点通知直达 App 内清算面板 | **近零**（照抄 `recIntent` 那几行） | 不是锁屏逐条打勾，但两分钟能清空今天 |
| **B** | `RemoteViews` + 自绘 XML，放 N 个 | 高：原生布局、每次刷新重建（现每 30 秒重画）、三星 / 小米等 ROM 表现不一致要真机验、**继承 §6.4 命中区偏移坑** | 真锁屏清算 |
| **C** | 第 4 个按钮拉起选择列表 | 中 | 折中，ROM 上交互不一致 |

**建议先做 A**，等 A 的数据告诉你「大家真的会逐条点」再考虑 B。

## 六、建议的实现顺序

1. **规则版「今天的账」**（纯本地 JS，零云成本）—— 先验证「这件事到底有没有用」。如果规则版算出来的账看了没感觉，接 AI 也救不回来。
2. **可回嘴 + 找模式**（同一台记忆引擎）—— 让账从第一天就不无聊。
3. **AI 判读**（前端直连）—— 升级措辞与重点选择，差异肉眼可见时这层价值才成立。
4. **通知栏清算台 A 方案** + 应用使用权限接入。
