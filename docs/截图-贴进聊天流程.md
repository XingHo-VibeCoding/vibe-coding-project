# 把「界面真实渲染截图」直接贴进聊天 —— 可复用流程

> 用途：改完界面想让人当场看到效果时，不要丢路径让人自己翻目录。
> 做法：用 Playwright 驱动本机 Chrome 真渲染 → 截指定元素 → 回复里用 Markdown 图片语法指向 PNG。
> 环境：Windows + 本机 Chrome + Node（无需装浏览器内核，复用系统 Chrome）。

## 前置检查（30 秒）

1. 有 Chrome：`C:/Program Files/Google/Chrome/Application/chrome.exe`
2. 有 playwright-core（本项目在 WorkBuddy 的 node 工作区里，见下方 import 路径；没有就 `npm i -D playwright-core`，**不要**装 `playwright` 全家桶去下浏览器）。
3. 静态服务在跑（本项目是 `http://127.0.0.1:4177/`，由 `skills/verify-project` 的 D1 项自动拉起）。
4. **改了源码必须先 build**（服务的是 `dist/`，不 build 截到的是旧界面 —— 最容易白跑一轮的坑）。

## 脚本模板（存成 `tmp/_shot-xxx.mjs`，node 直跑）

```js
import { chromium } from 'file:///<改成你的 node_modules>/playwright-core/index.mjs'

const URL = 'http://127.0.0.1:4177/'
const CHROME = 'C:/Program Files/Google/Chrome/Application/chrome.exe'

// 夹具数据：按需替换成你要展示的状态
const kv = {
  'web2.onboarded': '1',
  'web2.theme': 'light',
  'web2.exams': [ /* … */ ],
}

const browser = await chromium.launch({
  executablePath: CHROME,
  headless: true,
  args: ['--disable-gpu'],          // ⚠ 本机必须带，否则 rAF 不产帧、点什么都超时
})
const ctx = await browser.newContext({
  viewport: { width: 390, height: 844 },   // 常见手机尺寸
  deviceScaleFactor: 2,                    // 2x 像素，放大不糊
})
const p = await ctx.newPage()

// 在页面脚本跑起来之前把数据灌进 localStorage
await p.addInitScript((kv) => {
  for (const [k, v] of Object.entries(kv)) {
    localStorage.setItem(k, typeof v === 'string' ? v : JSON.stringify(v))
  }
}, kv)

await p.goto(URL, { waitUntil: 'networkidle' })
await p.waitForTimeout(700)

// 模拟点进目标页面
await p.evaluate(() => document.querySelector('[data-nav="me"]').click())
await p.waitForTimeout(500)
await p.evaluate(() => document.querySelector('[data-me-exams]').click())
await p.waitForTimeout(700)

// 只截目标元素，不截整页
await p.locator('[data-exam-list]').screenshot({ path: 'tmp/exam-pending-shot.png' })
await browser.close()
console.log('shot ok')
```

## 贴进回复

正文里写一行（路径相对当前工作目录；有空格用尖括号包起来）：

```md
![考试与复习：考场待公布](tmp/exam-pending-shot.png)
```

## 四条硬规矩

| 规矩 | 为什么 |
| --- | --- |
| 只截目标元素（`locator(...).screenshot()`），不截整页 | 整页带一堆无关内容，看图的人不知道你要他看哪 |
| 先 build 再截图 | 静态服务的是 `dist/`，不 build 截到旧界面 |
| 文件必须真存在 | Markdown 图片只是指针，文件没了就是破图 |
| 路径用相对路径 + 尖括号 | 绝对路径换机器就断；含空格不加尖括号会解析失败 |

## 一个诚实的前提

截图 = 脚本灌进去的**假数据**渲染出来的样子。它证明「界面在某种数据下长这样」，
不证明「真机上你的真实数据也这样」。要证明后者得真机跑。

## 附带说明：`--disable-gpu` 是什么

无头 Chrome 在没有 GPU 的环境里，合成器可能不产帧，
导致 `waitForTimeout` 之后的点击/截图全部超时。
加上它强制走软件渲染，稳定出帧。这是本机实测结论，不是通用要求。
