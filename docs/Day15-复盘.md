## 二、五轮修复的递进线

| 版本 | 触发反馈 | 根因 |
| --- | --- | --- |
| v1.23 | 引导页秒跳无动画 / 返回直接退出 / 节次裂成 4 段 / 滚轮不循环 | 缺方向动画；返回未分级；分块靠派生而非固化 `seg`；滚轮未循环化 |

| v1.25 | 数字诡异闪烁（快滑 + 循环边界时） | 拖动阶段仍调 `normalizeTop` 归位，跨份边界瞬间位移 → 闪 |
| v1.26 | 从 58 滚到 2，松手瞬间转一整圈 | 「归位」（瞬移）与「吸附」（动画）混算，整份位移被当成动画播了出来（实测视觉位移 63 格 vs 拖动 4 格） |
| v1.27 | 高速滑动不够丝滑 + 8:45 点不了 | 甩动动画用固定时长，与手指末速脱节（首速比 149%）；引导页那行里结束时间只是个 `<span>`，没有点击处理 |

两条隐藏线索：

1. **滚轮问题的深度是递进的，不是并列的。** `能滚 → 循环 → 跟手 → 不闪 → 不空转 → 丝滑`，每一轮都在解决上一轮改动新引入的副作用。这不是返工，是同一处耦合被逐层解开，直到 v1.27 才碰到真正的物理层（速度连续性）。
2. **一半的问题压根不在「手感」里。** 「8:45 点不了」的真身是那行里结束时间只是个 `<span>`，没有任何点击处理。截图给出的是现象，病根在 DOM 结构。

## 三、四条可迁移的经验

### 1. 手感可以量化

「丝滑」听起来是主观形容词，但可以翻译成**松手瞬间内容速度的突变率**：手指末速 1320px/s、动画首帧 1967px/s → 突变 +49% = 松手窜一下。翻译完，主观感受就变成可断言、可回归的数字（149% → 98%）。

遇到「感觉不对」时，第一件事是想清楚：**这个感觉对应的可测物理量是什么？**

### 2. 语义混算类 bug 最阴

「归位」是**瞬移**语义，「吸附」是**动画**语义。分开看每个函数都对、单测全绿、不报任何错 —— 但混在一起算，归位的那一整份位移就被当成动画播了出来（空转一整圈）。

对策：改这类代码前，先把每个动作的语义写进注释钉死，别让「平移」和「滚动」共用一个变量。

### 3. 先写测试、看着它红、再修

v1.26 那次：加 D 段断言 → 跑出 63.1 格（红）→ 改代码 → 4.0 格（绿）。有红 → 绿的证据链才敢说修好了；一上来就改代码的话，修完看到 4.0 格也不知道是真修好还是恰好没触发。

同一天在 NumberWheel 上又做了一次对照：断言在新版上 18/18 绿，临时回退旧版后 5 条红，且红的位置正是两个真实症状（跟手比 0.88、原生惯性一次快甩 17 格）。**断言必须能变红，否则就是假绿。**

### 4. 测量脚本比被测代码更常撒谎

当天 4 次误判，全部是尺子的问题，不是代码的问题：

- CDP 的 2ms 级时间精度不足，导致实测速度排序反跳；
- 合成的第一个 `touchmove` 被平台 touch slop 吞掉（发 12 次只投递 11 次）；
- headless 下 rAF 单帧速度噪声大（实测 0.63，理论 0.98）；
- 抖动阈值取 `ROW/2` 把真实的逐帧滚动吃成 0，断言变成永远 PASS。

准则：**测出来的数跟预期不符时，先验尺子，再怀疑代码。**

## 四、证据分级

| 手段 | 能证明什么 | 当天实证 |
| --- | --- | --- |
| 文件名 / hash 比对 | 什么都证明不了 | 发布是沙箱内重新构建，hash 会变（线上 `index-BOcPbvN6.js` vs 本地 `index-DgPp0LPl.js`）；线上 CSS 也比本地 dist 大 1257 字节 |
| 版本串 | 只证明「部署的是新版」 | 线上 JS 含 `v1.27` |
| **行为断言** | 「行为是对的」 | 源码 / dist / 线上三处 17/17，数字完全一致 |
| 三方逐字节 | 「手机里跑的就是验过的那份」 | `web2/dist` ↔ `app/www` ↔ APK 内 `assets/public` 一致 |

想闭环，四层得全占。当天为此新增了 `web2/tmp/verify-apk.py`：一条命令输出三方 hash、外壳注入与 `SHELL_VER`、JS 版本串、修复特征是否入包、各 `data-v` 段的 snap / touch-action。
