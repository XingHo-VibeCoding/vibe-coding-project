## 3. 发布到公网（静态托管）

```bash
cd D:/Document/Project/vibe-coding-project
tcb hosting deploy ./web2/dist app -e vibecoding-test-d5fqmhbb955e19dd --safe --verify
```

- `app` 是 **cloudPath**：发到 `/app/` 子目录（根目录是 Day 15 的「数据检查台」，别覆盖它）。
- `--safe`：**发布前自动备份**到 `.cloudbase-backup/<时间戳>/`，上传或校验失败自动回滚。**必带。**
- `--verify`：发布后比对远端与本地产物是否一致。**必带。**
- ⛔ **`--prune` 永远别用**：它会删掉「不属于本次发布」的远端文件。根目录的检查台就是这么被误删的。
- 成功标志三行都出现：`Deployment completed …` / `Post-publish consistency verification completed` / `Successfully uploaded 3 file(s)`。

**发布后立刻验证**（不能只看 CLI 说成功）：

```bash
U=https://vibecoding-test-d5fqmhbb955e19dd-1499011319.tcloudbaseapp.com/app
curl -s -o /dev/null -w "index %{http_code}\n" "$U/index.html"
for f in $(curl -s "$U/" | grep -oE 'assets/[A-Za-z0-9_.-]+'); do
  echo "$f -> $(curl -s -o /dev/null -w '%{http_code}' "$U/$f")"
done
```

三个都 **200** 才算发好。CDN 有缓存，页面没立刻变就用 `curl -H "Cache-Control: no-cache"` 或换无痕窗口看。

## 4. 留一份「v1.0 归档」——这是回退的唯一底牌

`tcb hosting` **只上传文件、没有版本管理**，它没有「退回上一版」按钮。所以每次正式发布，都把这一版的 `dist` 整份复制到归档目录：

```bash
cd D:/Document/Project/vibe-coding-project
mkdir -p release-archive/v1.0
cp -r web2/dist/* release-archive/v1.0/
```

本次 v1.0 归档内容（3 个文件，是回退时的「正确版本」）：

| 文件 | 大小 | sha256（前 16 位） |
|---|---|---|
| `index.html` | 614 B | `876c5e76c1228994` |
| `assets/index-Hq2TJ4FK.js` | 1,073,475 B | `be1162fc35d568ac` |
| `assets/index-PQrB60tz.css` | 158,543 B | `3abd100fea979de2` |

⚠ **2026-10-13 深夜起，「当前线上版本」已经是 `release-archive/v1.1/`**（v1.0 归档只是历史里程碑，**回退要用 v1.1**）。v1.1 归档内容（与线上逐字节一致，已实测）：

| 文件 | 大小 | sha256 |
|---|---|---|
| `index.html` | 614 B | `6193b5e44165d035840172dace012fa3eaa3442642fd55f8b20e1f80669b48db` |
| `assets/index-CKMp3UEx.js` | 1,095,839 B | `1a42e2bd036a54016fd8db8fbb1f320470ce5276aa1e6379c230253e7545c211` |
| `assets/index-DcOlDxCd.css` | 159,303 B | `f207256f41e8454a034d691fa4b6091d6baa1ed2191188dca6c35eca3c113904` |

**建立 v1.1 归档的原因**：本次修了 3 个用户报的 bug（教务核对页原生控件 / 导入后不落今日页 / 引导层出口文案）并把全项目 10 处原生表单控件清零。旧 v1.0 归档**不含这些修复**，拿它回滚会把已修的 bug 一起带回来。归档规则不变：**发一次版留一份，回退拿最新那份**。

**归档进不进仓库？** `release-archive/` 是**发布底牌**、体积小（1.2 MB）、每次发版都要留，所以**进仓库**（跟 `docs/shots/` 一个道理：是可复现的发布物证，不是构建垃圾）。注意演练用的坏版本 `release-archive/_drill-bad/` **已被 `.gitignore` 忽略、不入库**。

⚠ **必须配 `.gitattributes`**：本机 `core.autocrlf=true`，若不干预，git 检出归档时会把 LF 换成 CRLF，**归档就和线上对不上了**（sha256 校验一跑就露馅）。仓库根已有：

```
release-archive/** -text
```

`-text` = 不做任何行尾转换，进库与检出都逐字节原样。**新增发布归档目录时不用改**（`**` 覆盖）。

## 5. 顺带出手机包（要装机时才做）

```bash

$env:SHIP_JAVA_HOME='D:\Tools\zulu21.52.203-ca-jdk21.0.12.1-win_x64'
& D:\Node.js\node.exe scripts/ship.js
```

- **`$env:JAVA_HOME` 在本机是空的**，必须用 `SHIP_JAVA_HOME` 传 JDK 路径，否则 gradle 找不到 java。
- 一条命令做完 5 步（web2 构建 → sync → patch-android → gradle → 归档 `dist-apk/` → `verify-apk.py` 三校），任一步失败立刻非 0 退出。

- **注意**：每次 ship 都**覆盖同名文件**（版本号没变时文件名相同）。
- 装机（用户手动，或 adb）：`adb install -r dist-apk/<包名>.apk`。

## 6. 已知的坑（都是真踩过的）

1. **子目录白屏 = 忘了 `base: './'`**。Vite 默认引用绝对路径 `/assets/…`，只有放在根目录才找得到；发到 `/app/` 就 404。`web2/vite.config.js` 里必须有 `base: './'`。
2. **PowerShell 把 stderr 当错误报 `[exit code: 1]`**。`npm.cmd`、`git`、`tcb` 在 PowerShell 里都会因为写 stderr 而被标成失败——**看末尾的成功字样，别只看退出码**。
3. **`tcb hosting deploy` 目录形式的校验**：本环境历史上「目录形式校验不过」，带 `app` 作 cloudPath 就正常。发子目录时**一定带 cloudPath**。
4. **首访落腾讯云「风险提醒」中间页**：这是免费托管域名的固有行为，点「确定访问」才进站。不是故障。
5. **别人浏览器里 AI 三项是死的**：转写 / 纪要 / 课表识别要 API Key，只有本机配过。这是已知代价，不是这次发布的回归。
