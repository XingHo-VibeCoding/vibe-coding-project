## 今日页头部上拉收缩（乙）· 落地口径（2026-10-09）

**问题**：今日页的问候卡（问候语 + 顶卡 + 计数条 + 学期进度带）固定在滚动窗口**外**，占掉可用高度的 32%（273px），但它自己不参与滚动 —— 一屏只能装 3 条「接下来」，而这 273px 一直在那儿。

**唯一的结构决定：头部必须是 `absolute` 浮层，不能留在文档流里。**

推导（为什么「收起来留在流里」不行）：若头部在流内、上拉时把自身高度收掉 `s`，则「滚动窗口的顶」也随之**上移 s**，而窗口自己的 `scrollTop` 也是 `s` ⇒ 列表内容相对手指走了 `s(窗口上移) + s(滚动) = 2×`，**以两倍速度飞走**；更糟的是 `scrollTop` 会被浏览器反复夹回（窗口刚变矮就夹一次），手感是「一顿一顿」。要让内容 **1:1 跟手**，只有一条路：**让滚动窗口自己不动** —— 头部 `position: absolute` 浮在上面，`main[data-page="today"]` 的高度就是整块可用高度（不再靠 `measureTodayH()` 反推），滚动内容加一段**与展开态等高的常量 padding-top**。

**关键：这段 padding 必须刻意不随滚动变**（`heroContentPad = heroOpenH + HERO_CONTENT_PAD`）。一旦让它跟着收缩变小，就又变回 2× —— 压缩/走掉全程只做**视觉**（`height` 裁切 + `opacity` + `translateY`），**不触发布局**，所以窗口高度恒定，不会出现「内容缩了、底部空一条」。

**`web2/src/App.vue` 里的量**（`HERO_WRAP_PAD = 12` 是浮层顶部留白，原 header 的 `mt-3` 搬进来；`HERO_CONTENT_PAD = 16` 是内容原本的 `pt-4`；`heroFullH` / `heroBarH` 由 `measureHero()` 量 `heroRef` / `heroBarRef` 的 `offsetHeight`）：

| 量 | 含义 |
|---|---|
| `heroActive` | `tab === 'today' && !heroLocked && heroOpenH > heroMinH` —— 只有今日页、没被锁、且**确实有得收**时才参与 |
| `heroP` | `clamp01(heroScroll / heroCompressLen)`，0 = 展开 → 1 = 只剩一行（1:1 跟手） |
| `heroT` | 折到底后再上拉：`clamp01((heroScroll − heroCompressLen) / heroMinH)`，把整块推走 |
| `heroWrapH` | 浮层高度 = `heroOpenH − heroCompressLen·heroP − heroMinH·heroT`；**别的 tab 返回 `null`**（不写内联高度，交回外层 grid 的 0fr 收起） |
| `heroTranslateY` | `heroMinH · heroT` |
| `heroFullOpacity` | `max(0, 1 − 1.6·heroP)`（头卡淡出） |
| `heroBarOpacity` | `clamp01((heroP − 0.5)·2)`（状态条 50% 之后才淡入 —— 早于 50% 会两套文案叠着看不清） |
| `heroLocked` | `!!recActiveId \|\| !!reviewSheet` ⇒ 录音中 / 复盘浮层开着时 `heroP`、`heroT` 恒 0，头部停在展开态 |
| `onTodayScroll()` | 用 `requestAnimationFrame` 去抖，回调里读 `todayRef.scrollTop` 写 `heroScroll` |

**`measureHero()` 只涨不跌**（`if (h > heroFullH.value) heroFullH.value = h`）：切回今日页时 header 的 padding 类从紧凑版切回展开版有 280ms 过渡，`watch(tabIndex)` 的 `nextTick` 会量到「还没长开」的值；一旦写小，`heroContentPad` 跟着变小 ⇒ `scrollHeight` 变小 ⇒ 浏览器立刻夹掉 `scrollTop`，**位置丢失**（实测 `246 → 73`）。这与文件里既有的 `todayTopOffset` 是同一条理由，2026-10-05 已为它实证过一次。

**带出的一处真回归（务必记住）**：内容平移层 strip 的内联 `height: stripH + 'px'` **同时也带 280ms 的 `transition-property: height`**。外壳让位（`--sat` 生效）让课表页高度 `839 → 811` 正好一个状态栏，这 280ms 的「慢慢降」期间 strip 比 root 的 `min-height` 高，文档就多出最多 **23px** 可滚（`week-fit-check` G3/G4 挂在「只等 100+250ms」上）。修法是新增 `stripInstant`（`markStripInstant()` 在 `onWinResize()` 第一行调用，把 `transition-duration` 压到 0ms，300ms 后恢复）：**外壳让位不是导航、是布局重定义，本来就该瞬时；切 tab 的滑动过渡不动**。

**踩坑留档**：判断这类高度问题必须**同时打印 `strip.style.height` 与 `strip.offsetHeight`** —— 浏览器对 flex 容器在 `height` 过渡期间的 `offsetHeight` 读取会滞后/取整，两者能差几百 px，只看一个会得出互相矛盾的结论。

**自检**：`web2/tmp/hero-collapse-check.mjs` **26 过 / 0 挂**，四条关键断言 —— A1 `header.closest('[data-today-scroll]') === null`（头部真的在滚动窗口外）、B1 内容位移 == `scrollTop`（**1× 不是 2×**）、B4 窗口高度全程恒定、F1 课表页头部整块裁掉（`clipH < 2`）。配套 `today-shell-check` 17/0、`week-fit-check` 19/19、`week-menu-check` 22/0、质量门 0 处问题。
