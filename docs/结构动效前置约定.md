### 时间行规格演进：26px 文字行 → **50px 卡片**（2026-10-09，W 方案）

**旧规格（26px 时间行，2026-10-04 定，2026-10-09 退休）**：

- 行高 **26px**：`py-[3px]` + `text-[11px]`。
- **触区规则**：26px 行**只做展示**，不把整行撑成 44px；点击靠行右侧动作按钮（≥44px 热区）或长按。否则 20 件就是 880px，密度白省。
- D↔F 换密度时**行高不变**，只换滚动窗口里的内容。

⇒ **2026-10-09 用户拍板 W 方案后作废**：今日页「接下来」的条目**改成一行一张 50px 卡片**（`web2/src/components/RowItem.vue` 重写）。理由是纯文字行「一屏 5 件长得一样、一眼扫不出下一件要干什么」。

**现规格（50px 时间轴卡）**：

- 卡高 **50px** = 标题 `leading-[20px]` + 副信息 `leading-[16px]` + `py-1.5`（6+6）+ 上下边框（1+1）。**副信息为空时补一行 `&nbsp;` 空气**，否则卡片会塌到 34px。
- 结构三列：时间列 `w-10`（固定 40px）→ 竖轴 `w-[2px]`（普通卡 `bg-soft-2`，进行中 `bg-primary-500`）→ 右侧 `min-w-0 flex-1` 放标题 + 副信息；`meta`（剩余分钟 / 已上完）在最右。
- **进行中的卡 = 同一张卡换状态**：`border-primary-200 bg-primary-50` + 蓝轴 + `font-semibold text-primary-600`。不是第二种造型，一屏不会出现两种卡。
- **触区靠卡片自身身高**：50px ≥ 44px，所以**去掉了**旧规格那套 `after:-inset-y-[9px]` 外扩补丁。
- **已完成 / 已过仍是实色** `text-ink-dim`；**禁止** alpha 档（A4 可读性扫描结论：alpha 档在白底与浅灰底都不到 WCAG AA）。
- **锚点不变**（`data-row` / `data-row-state` / `data-row-time` / `data-row-sub` / `data-today-item`），改规格不动测试断言的定位方式。
- **折叠行 / 展开按钮仍是 26px 文字行**：`data-today-past-fold` 与 `data-today-expand` 是**控制**不是「要做的事」，不跟着卡片化。
- D↔F 换密度时**卡高不变**（都是 50px），只换滚动窗口里的内容。

## 今日页头部上拉收缩（乙）· 落地口径（2026-10-09）

**问题**：今日页的问候卡（问候语 + 顶卡 + 计数条 + 学期进度带）固定在滚动窗口**外**，占掉可用高度的 32%（273px），但它自己不参与滚动 —— 一屏只能装 3 条「接下来」，而这 273px 一直在那儿。

**唯一的结构决定：头部必须是 `absolute` 浮层，不能留在文档流里。**

推导（为什么「收起来留在流里」不行）：若头部在流内、上拉时把自身高度收掉 `s`，则「滚动窗口的顶」也随之**上移 s**，而窗口自己的 `scrollTop` 也是 `s` ⇒ 列表内容相对手指走了 `s(窗口上移) + s(滚动) = 2×`，**以两倍速度飞走**；更糟的是 `scrollTop` 会被浏览器反复夹回（窗口刚变矮就夹一次），手感是「一顿一顿」。要让内容 **1:1 跟手**，只有一条路：**让滚动窗口自己不动** —— 头部 `position: absolute` 浮在上面，`main[data-page="today"]` 的高度就是整块可用高度（不再靠 `measureTodayH()` 反推），滚动内容加一段**与展开态等高的常量 padding-top**。

**关键：这段 padding 必须刻意不随滚动变**（`heroContentPad = heroOpenH + HERO_CONTENT_PAD`）。一旦让它跟着收缩变小，就又变回 2× —— 压缩/走掉全程只做**视觉**（`height` 裁切 + `translateY`），**不触发布局**，所以窗口高度恒定，不会出现「内容缩了、底部空一条」。

**（2026-10-10 修订）头卡由「淡出」改「真收缩」**：原实现给头卡挂 `opacity: max(0, 1 − 1.6·heroP)`（拉到 62% 整卡透明）并让状态条从 50% 淡入，两者在 50%~62% 重叠 —— 用户 m00943 判定「这是淡出效果，不是收缩」，要求改成与「今日 → 周课表」同一手法的**真收缩**：头卡全程不透明，高度整块塌掉，下方内容自然顶上。落地方式：`heroHeaderStyle` 把 `heroFullH·(1−heroP)` 写进 header 的内联 `height`（header 是 `border-box`，光把 height 归零还留 `2×20px` padding 的渐变底压在状态条后面 ⇒ 纵向 padding 一起乘 `(1−heroP)` 塌掉），并把 `transitionProperty: 'none'` 内联上去（滚动期间加过渡会跟手指打架，做不到 1:1）；状态条仍是 `opacity`，但收窄到**最后 10%**（`heroP > 0.9`）才露出。`heroFullOpacity` 已删除。

**（2026-10-10 二次修订①）折到底后钉住，不再走掉**：用户 m01369「塌掉以后上面这个小卡片就不随着上滑继续上升好了，反正不占空间」。原实现还有一段「走掉」位移（`heroT = clamp01((heroScroll − heroCompressLen) / heroMinH)` + `heroTranslateY = heroMinH · heroT`，折到底后继续把状态条推出视野）。现已**整体删除** `heroT` / `heroTranslateY`，`heroP` 到 1 就封顶；`heroWrapH` 里那项 `− heroMinH·heroT` 一并去掉。`hero-collapse-check` 的 D 组口径相应反转：D1 由「浮层顶边 < −20（走掉）」改为「顶边不动（±1）」、新增 D3「浮层高仍是一行」。

**（2026-10-10 二次修订②）切页动画被 `heroHeaderStyle` 掐死（用户报的 bug）**：`heroHeaderStyle` 原来在 `heroP === 0`（没在收）时也照常返回内联定高 + 纵向 padding + `transitionProperty:'none'`。于是**从周课表切回今日的那一帧**，内联样式立刻接管，header 自己的 280ms padding 过渡当场失效 —— 探针实测 `周课表 → 今日` 在 **+1ms** 就完成 `229 → 273`，之后 19 帧纹丝不动，看上去就是「啪」地跳到位。修法：`heroP <= 0` 时返回 `null`，把过渡还给 CSS；只有在真收的时候才接管。（`今日 → 周课表` 方向本来就是外层 grid 的 0fr 过渡，不受影响。）

**（2026-10-10 二次修订③）自检脚手架的假失败**：`hero-collapse-check` 原来用 `page.evaluate(设 scrollTop) + page.waitForTimeout()` 来滚动。但 `onTodayScroll` 是 **rAF 去抖**的，而 headless Chrome 在没有合成帧时**不会自己推进 rAF**（实测单帧等 47 秒）⇒ `scrollTop` 变了、`heroScroll` 没更新，B2/C1/C2/C3/D3/G5/H1 七条集体假挂。修法：`scrollTo()` 改成在同一段 `page.evaluate` 里 `await` 6 个 `requestAnimationFrame` 再返回。**凡是驱动该项目 rAF 去抖逻辑的脚本，都必须这么写。**

**（2026-10-12 三次修订）钉住之后露出的两件事：叠字与触区**：折到底改为钉住（二次修订①）后，浮层与下方滚动内容**长期共处一屏**，而头卡此时已塌成 `height: 0` ⇒ 两个问题暴露出来：

- **叠字**：浮层 `[data-hero-wrap]` 与状态条都没有背景色（实测 `rgba(0,0,0,0)`），下方待办文字直接从状态条背后透上来。用户 m02029 拍板 **A｜浮层铺页面底色**：today 分支加 `bg-canvas`（`--color-canvas` = 浅色 `#f5f7fa` / 深色 `#0c111d`，随主题走）。实测重叠区（css y 73..84）暗像素占比由 **33.87% → 19.91%**。曾试过 B「纯色底 + 底部 8px 渐隐」（23.80%，覆盖不全）与 C「82% 底色 + `backdrop-filter: blur(12px)`」（19.91%，与 A 等效但更贵）—— 选 A。展开态铺不铺一样（头卡是不透明渐变卡，盖在上面看不见底）。自检新增 **C4「折到底浮层有底色（不透明）」**。
- **触区**：状态条按钮本体高 34px（`h-8` 再加按钮自身），靠 `after:absolute after:inset-x-0 after:-inset-y-1.5` 上下各扩 6px 撑到 46px；但浮层的 `overflow-hidden` 会把下沿裁掉，而 `heroMinH` 只有 `heroBarH + HERO_WRAP_PAD = 32 + 12`，**底部留白 0** ⇒ 实际可点高度只有 **39px**（下沿 y=84 落到 `MAIN`）。修法：新增 `HERO_WRAP_PAD_BOTTOM = 8` 并加进 `heroMinH` ⇒ 收起高度 **44px → 52px**（12 顶白 + 32 条 + 8 底白），触区补满 46px。自检 H1 断言同时收紧：从「中心命中 + 上下任一处命中」改为**竖扫数出真实可点像素跨度 ≥44px**（旧断言太弱，39px 也能过）。

**（2026-10-12 四次修订）切页仍硬跳的真凶：学期进度带在塌缩格之外**（用户 m02386 报「现在可以修复页面切换动画了」，即二次修订②之后**仍未修好**）：

- **现象**：二次修订②只治了「`heroHeaderStyle` 用内联 `transitionProperty:'none'` 掐死过渡」那一半，切页依旧硬跳，而且**两个方向都跳**：`周课表 → 今日` header 高第一帧 `76 → 120`（**+44px**），`今日 → 周课表` 第一帧 `273 → 229`（**−44px**）。两者都出现在 `postSync` 之后、第一个 rAF 之内（`postSync` 值与 `pre` 相同 ⇒ 不是同步 click 阶段造成的）。
- **定位**：`web2/tmp/tabswitch-boxdump.mjs` 逐子元素量盒模型 —— 今日态 header `offsetH=273` 有三个 kid：kid#0 高 55.5、kid#1（`grid grid-rows-[1fr]`）高 133、**kid#2 `mt-3` 高 32.5 + margin-top 12px**；周课表态 `offsetH=76` **只有两个 kid**，kid#2 整个不存在。差额 `32.5 + 12 = 44.5px`，正好等于实测跳变。`tabswitch-ribbon-check.mjs` 做运行时 A/B：注入 `[data-term-ribbon]{display:none !important}` 后再切，六帧全部停在 `hH=76`，跳变消失 ⇒ 根因锁定。
- **根因**：`data-term-ribbon`（学期进度带）当时写成 `v-if="tab === 'today' && termInfo"`，且挂在 header 内**「主体」那个 `1fr/0fr` 塌缩格之外**。切页时 `tab` 一变，`v-if` 立刻插入/移除该块，而 grid 的展开/塌缩要走 280ms —— 新插入的 44.5px 不参与过渡，第一帧就顶出来。方向不对称（进今日是「插入」、出今日是「移除」）正是 `v-if` 的特征。

- **口径教训（写进规矩）**：**凡是切页要增减高度的东西，必须放进那个 `1fr/0fr` 塌缩格、由它统一裁切**；header 里任何「随 `tab` 增删、又在塌缩格之外」的块都会造成切页瞬时跳变。二次修订②的结论「`今日 → 周课表` 方向不受影响」是**错的** —— 该方向也跳，只是当时没量到。

**`measureHero()` 只涨不跌**（`if (h > heroFullH.value) heroFullH.value = h`）：切回今日页时 header 的 padding 类从紧凑版切回展开版有 280ms 过渡，`watch(tabIndex)` 的 `nextTick` 会量到「还没长开」的值；一旦写小，`heroContentPad` 跟着变小 ⇒ `scrollHeight` 变小 ⇒ 浏览器立刻夹掉 `scrollTop`，**位置丢失**（实测 `246 → 73`）。这与文件里既有的 `todayTopOffset` 是同一条理由，2026-10-05 已为它实证过一次。

**带出的一处真回归（务必记住）**：内容平移层 strip 的内联 `height: stripH + 'px'` **同时也带 280ms 的 `transition-property: height`**。外壳让位（`--sat` 生效）让课表页高度 `839 → 811` 正好一个状态栏，这 280ms 的「慢慢降」期间 strip 比 root 的 `min-height` 高，文档就多出最多 **23px** 可滚（`week-fit-check` G3/G4 挂在「只等 100+250ms」上）。修法是新增 `stripInstant`（`markStripInstant()` 在 `onWinResize()` 第一行调用，把 `transition-duration` 压到 0ms，300ms 后恢复）：**外壳让位不是导航、是布局重定义，本来就该瞬时；切 tab 的滑动过渡不动**。

**踩坑留档**：判断这类高度问题必须**同时打印 `strip.style.height` 与 `strip.offsetHeight`** —— 浏览器对 flex 容器在 `height` 过渡期间的 `offsetHeight` 读取会滞后/取整，两者能差几百 px，只看一个会得出互相矛盾的结论。
